# mac-server-kit

Installer and runtime scripts for a macOS home server: a base media stack (Gluetun, qBittorrent, arrs, Seerr, Plex/Jellyfin, Homarr, Glances, health monitoring, backups) plus optional modules. Full design and decisions: `docs/design.md`. Read it before making changes.

## Working rules

- **Bash 3.2, no dependencies.** Scripts must run on stock macOS `/bin/bash` (no associative arrays, `mapfile`, `${var,,}`). No jq, yq, gum, or anything that needs Homebrew. Some target Macs can't run Homebrew.
- **Nothing machine-specific in tracked files.** No tailnet names, hostnames, usernames, emails, keys or paths under a real home folder. The repo may go public later and its whole history with it. Machine specifics live in the untracked answers file, secrets file, `compose.override.yml` and `~/server/local-modules/`.
- **Three kinds of files, never mixed:**
  1. *Generated*: rebuilt on every install run, never hand-edited (`.env`, launchd plists, `serve.json`, the enabled-module list).
  2. *Seeded*: created only if missing, never overwritten (app configs in appdata, settings pushed through app APIs, Homarr apps/integrations).
  3. *User-owned*: never overwritten or regenerated by the installer (answers file, secrets file, `compose.override.yml`, local modules). The only installer writes are appending missing keys to the answers and secrets files and editing the answers file's `MODULES=` line. Random app secrets live in the seeded `~/server/kit/generated-secrets.conf`, which backup-config and restore-config must include. Outside `~/server`, the kit writes only one marked PATH line appended to `~/.zprofile` (skip-if-present) and its generated launchd plists, `~/Library/LaunchAgents/io.github.andy327.mac-server-kit.*.plist` (launchd loads a user's jobs at login only from there); native apps it installs go into `APPS_DIR` (default `/Applications`; `~/Applications` keeps them in one account).
- **One idempotent install path.** `./kit add <module>` re-runs install with the module enabled. Every step is skip-if-done.
- **Runtime scripts read the enabled-module list at runtime.** Don't generate per-machine script copies.
- **Naming:** install-time commands go through `./kit` (`install | check | add | disable | status`). Runtime scripts installed to `~/server/bin` are verb-first (`update-all`, `backup-all`, `backup-<module>`, `restore-<module>`, `check-health`, `start-maintenance`, `end-maintenance`).
- **launchd labels:** `io.github.andy327.mac-server-kit.<job>`.
- **Steps that may fail across app versions warn and continue** (Homarr API calls in particular). They never abort the install.
- **Git:** never script or run git commands on the server machine. The owner does all repo updates there by hand.
- Run `shellcheck` on scripts when it's available on the dev machine. It isn't required on target machines.
